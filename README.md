# מערכת הדיוור של נקודה (nekuda-mailer) — גרסה 0.9.0

מערכת דיוור עצמאית: רשימות תפוצה, בונה גליונות רספונסיבי בעברית, תור שליחה, מעקב פתיחות וקליקים, הסרה בלחיצה אחת וטיפול בקפיצות.

אין תלויות חיצוניות. נדרש רק Node.js בגרסה 22.5 ומעלה. הנתונים נשמרים בקובץ SQLite אחד בתיקיית `data`.

## הפעלה מקומית (Windows, Mac או Linux)

```
npm start
```

ואז לפתוח את http://localhost:3080. בהפעלה הראשונה המערכת מבקשת לבחור שם משתמש וסיסמה למנהל.

בדיקות: `npm test` (מריץ שרת SMTP מדומה ובודק את כל המסלול מקצה לקצה).

משתני סביבה: `PORT` (ברירת מחדל 3080), `HOST` (ברירת מחדל 127.0.0.1), `DATA_DIR` (ברירת מחדל `./data`).

## מה כלול בגרסה 0.9.0

- נמענים: חיפוש, סינון לפי מצב ורשימה, הוספה, עריכה, מחיקה.
- רשימות תפוצה, כולל יצירת רשימה מתוך מי שפתחו, לא פתחו או לחצו בגליון.
- ייבוא מ-CSV או מהדבקה (גם כרשימת הסרה), וייצוא ל-CSV.
- בונה גליונות בבלוקים: כותרת, טקסט עשיר, תמונה, כפתור, שני טורים, קו מפריד, רווח, תחתית. תצוגה מקדימה למחשב ולנייד.
- מצב "HTML מוכן" להדבקת גליון שנבנה בתוכנה אחרת.
- תגים אישיים: `{{name}}`, `{{first_name}}`, `{{email}}`, `{{unsubscribe_url}}`, `{{webview_url}}`.
- שליחת בדיקה, שליחה מיידית, תזמון, השהיה והמשך. שליחה חוזרת מגיעה רק לנמענים חדשים.
- קצב שליחה ותקרה יומית (לחימום כתובת IP חדשה), ניסיונות חוזרים אוטומטיים.
- כותרות `List-Unsubscribe` ו-`List-Unsubscribe-Post` (הסרה בלחיצה אחת), וקישור הסרה אוטומטי אם חסר.
- מעקב פתיחות וקליקים, נתונים לכל גליון ולכל קישור.
- קפיצות: קפיצה קשה חוסמת מיד, שלוש קפיצות רכות חוסמות, תלונת ספאם מסירה.
- טופס הרשמה ציבורי בכתובת `/subscribe`.

## מה עדיין לא כלול

- ייבוא שדות מותאמים מקובץ CSV (כרגע ממלאים אותם בחלון עריכת הנמען).
- בחירת מנצח אוטומטית בבדיקת A/B (כרגע חלוקה שווה והשוואה במסך הנתונים).
- מתוך מסמך ההמלצות לעורך: מנוע MJML (ה-HTML מופק במנוע טבלאות משלנו), עורך תמונות ובנק תמונות, ספריית תבניות רחבה, בלוק טיימר וקוד QR.

הכניסה עם Google נבדקה מול ספק מדומה בלבד, ולא מול Google עצמו.

מסלולי ההצפנה של SMTP (STARTTLS ו-TLS) כתובים אבל לא נבדקו מול שרת אמיתי. המסלול שנבדק הוא שרת מקומי בלי הצפנה, עם ובלי הזדהות.

## פריסה על שרת משלך (מומלץ: דרופלט עם Postfix)

זה המבנה של המערכת הישנה: האתר מוסר את המיילים ל-Postfix מקומי, והוא שולח וחותם. אין עלות לכל מייל.

1. להתקין Node.js 22 ומעלה, ולהעתיק את התיקייה אל `/opt/nekuda-mailer`.
2. ליצור משתמש מערכת: `useradd -r -s /usr/sbin/nologin nekuda` ולתת לו בעלות על `/opt/nekuda-mailer/data`.
3. להעתיק את `deploy/nekuda-mailer.service` אל `/etc/systemd/system/` ולהריץ `systemctl enable --now nekuda-mailer`.
4. להגדיר nginx לפי `deploy/nginx.conf` ולהנפיק תעודת TLS.
5. להגדיר את Postfix ו-OpenDKIM לפי `deploy/postfix.md`.
6. להיכנס לאתר, ליצור מנהל, ולמלא במסך ההגדרות את כתובת האתר, כתובת השולח וכתובת הקפיצות.

## פריסה על Render (אפשרי, עם שתי מגבלות)

- Render חוסם את פורט 25 לכל השירותים, ואת 465 ו-587 במסלול החינמי. לכן נדרש מסלול בתשלום ושירות שליחה חיצוני (SMTP עם שם משתמש וסיסמה), שמוגדר במסך ההגדרות.
- נדרש דיסק קבוע, אחרת המסד נמחק בכל הפעלה מחדש.

הקובץ `render.yaml` מגדיר שירות כזה עם דיסק. הוא יוצר שירות חדש בשם `nekuda-mailer` ואינו נוגע בשירותים קיימים.

## רשומות DNS שצריך להוסיף (בלי לשנות קיימות)

| סוג | שם | ערך | הערה |
| --- | --- | --- | --- |
| A | תת-דומיין חדש לאתר | כתובת ה-IP של השרת | אפשר דרך הפרוקסי של Cloudflare |
| A | תת-דומיין חדש לשרת הדואר | כתובת ה-IP של השרת | בלי פרוקסי (DNS only) |
| TXT | סלקטור DKIM חדש | המפתח הציבורי מ-OpenDKIM | לצד הסלקטור הקיים |

רשומת ה-SPF הקיימת צריכה לקבל את ה-IP של השרת החדש (תוספת, לא החלפה). בנוסף נדרשת רשומת PTR לכתובת ה-IP, שמוגדרת אצל ספק השרת.

## מעבר מהמערכת הישנה (AcyMailing)

1. במערכת הישנה: משתמשים, יצוא. לבחור את השדות `email` ו-`name`, קידוד UTF-8, ולכל רשימה שרוצים להעביר לסמן "נרשמים".
2. במערכת החדשה: ליצור רשימה, ואז ייבוא, להעלות את הקובץ ולסמן את הרשימה.
3. חשוב: לייצא גם את מי שהוסרו (לסמן "הוסר מהרשימה") ואת הרשימות "חסומים", ולייבא אותם בתור "רשימת הסרה". כך מי שביקש הסרה לא יקבל מיילים מהמערכת החדשה.
